# 上游标准如何引用

- **版本**：v0.2.6
- **日期**：2026-08-18
- **上游仓**：私有教学质量业务文档仓（与本仓放在同一层目录即可打开原文；**不要**把上游整仓固定为 submodule，除非维护者另行决定）
- **产品源**：[就业守护产品说明](../01-product/001_prd_就业守护助手产品说明.md)

---

## 1. 原则

- **业务口径以上游为准**。本仓提示词只执行上游已经写明的标准，不另定标准。
- 引用时写明上游相对路径与文首版本号，便于回溯。
- 冲突时以上游最新正文为准，并改回本仓摘要与日后的 `prompts/`。
- **不要**把课评「好课标准」或课研打分表用到简历与面试作答上。
- 就业标准未定稿前，「判能不能投」和「查排版」用的合格线须由维护者书面确认后再改；定稿后改引上游并升高版本。没有书面合格线，这两个评价工具不要开始做。
- **判能不能投**与**面试评价**不共用检查项：前者问能不能投，后者问这一场作答卡在哪。提示词按工具拆开，不要混用。
- 本仓为 public 仓库：上游文中若有维护者真名、机构名或对外品牌名，**不要抄进**本仓文档与提交说明。

## 3. 提示词写入仓库（实现阶段）

提示词按**工具**拆开，不要把老师用的一条命令里所有步骤的口径塞进同一份提示词：

```text
prompts/
  system_tone.md       # 合格线 / 水平线、文风、对事不对人
  check_layout.md      # 查排版（只看页图；合格线须维护者确认）
  judge_resume.md      # 判能不能投（内容标准须维护者确认后再改）
  draft_questions.md   # 按项目练习题（标明推测，不是真题）
  review_projects.md   # 项目审阅含金量 / 难度档（不含薪资；见 005）
  extract_qa.md        # 从逐字稿还原问答
  review_interview.md  # 面试评价（不要套用简历内容标准）
```

PDF 出图、读简历、转写录音以程序为主，不另写评价提示词。变更评价维度时：先确认上游已有表述（或维护者书面确认临时合格线）→ 更新本仓产品说明或本文 → 再改对应工具的 `prompts/` → 用同一份脱敏样例对比输出差异。
