# 判能不能投技术说明

- **版本**：v0.4
- **日期**：2026-09-08
- **对应工具**：`employ-guard judge-resume`
- **标准**：[004 简历合格线 §2](../04-standard/004_resume-bar_简历合格线.md)（C1：首页岗位类表述，v0.2.2）
- **提示词位置**：`src/employ_guard/judge_resume.py` 中 `SYSTEM_PROMPT`
- **汇总逻辑**：`src/employ_guard/judge_aggregate.py`

## 1. 锁定结论

| 项     | 口径                                                                                                                   |
| ------ | ---------------------------------------------------------------------------------------------------------------------- |
| 输入   | PDF（须已有 `{stem}.resume.md`）或简历 Markdown / 文本                                                                 |
| 正文源 | **优先** `{stem}.resume.norm.md`（parse 之后）；无则回退抽出正文；记 `used_normalized`                                 |
| 看什么 | **内容**仍只看文本；**不**凭页图评排版。同目录若有 layout / writing / profile / skills / projects，则**汇总进报告**    |
| 输出   | `{stem}.judge.md` / `{stem}.judge.json`；总览 / 内容结论分写；含「排版与文字表达」「时间检测汇总」；合格线与水平线分栏 |
| 终端   | 单独跑本工具：内容达标 / 未达标。老师命令 `resume`：**排版 / 文字表达 / 内容任一未过 → 退出码 `2`（未过合格线）**      |
| C1     | 有 `{stem}.profile.json` 时 **以 check-profile 为准**；无 profile 时仍用首页规则层兜底                                 |
| 技术   | **C3 / C8** 主要映射 `check-skills` + `review-projects`；有产物则覆盖 LLM 同项                                         |
| 不做   | 不替代各分项单独再跑；不打百分制分数；不出练习题；R26 brief 另开                                                       |

## 2. 检查怎么实现

| 编号 / 段               | 实现方式                         | 说明                                                                                                     |
| ----------------------- | -------------------------------- | -------------------------------------------------------------------------------------------------------- |
| **前置已覆盖**          | **汇总覆盖**                     | profile→C1；skills/projects→C3、C8（及结构缺口→C4 存疑、P4→C5 存疑）；projects 时间旗→时间汇总 / C7 存疑 |
| **C2 / C6 / C9 等缺口** | **LLM + 既有规则**               | 前置未写的项仍由 LLM / 规则补洞                                                                          |
| **C1（无 profile）**    | **LLM + 规则**                   | 首页无岗位类表述 → 未合格                                                                                |
| **时间检测汇总**        | **规则为主**                     | 结束年月晚于检查日；P2 / P5～P8 / G1-T 等写入独立章节，并酌情写入 C7 存疑                                |
| **排版 / 文字表达**     | **只读同目录 JSON**              | 写入报告分节；`overall_pass` = 内容全过 ∧ layout≠false ∧ writing≠false；缺文件不当否决                   |
| **H1～H8**              | **LLM + 规则封顶**（仅内容全过） | 与汇总后的 pass_line 一致封顶                                                                            |

LLM：OpenAI 兼容 Chat Completions；默认 `LLM_MODEL`（见 `.env`）。DeepSeek V4 默认关闭 `thinking`；优先 `response_format: json_object`，`max_tokens` 8192。失败按策略重试最多 3 次。用户消息带「检查当日」日期。

## 3. 失败约定

| 情况                         | 行为                                                     |
| ---------------------------- | -------------------------------------------------------- |
| 无简历文本等                 | 失败说明，退出码 `1`                                     |
| 单独跑：内容未过合格线       | 写出报告；终端「内容未达标」；退出码 `2`                 |
| `resume`：排版/文字/内容未过 | 写出各报告；终端「未过合格线」；退出码 `2`（分项仍分开） |
