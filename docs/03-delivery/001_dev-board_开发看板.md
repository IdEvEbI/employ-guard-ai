## 2. 里程碑总表

| 里程碑         | 目标                                                                 | 何时开 Issue                            |
| -------------- | -------------------------------------------------------------------- | --------------------------------------- |
| **M0**         | 仓库基础、产品说明、本文、本仓 Cursor Rule                           | 已完成（#1～#7）                        |
| **投前看简历** | 各个简历工具可单独跑；`resume` 能按顺序跑完                          | M0 完成后；先做不依赖标准的出图与抽文本 |
| **听后做复盘** | 转写、还原问答、面试评价可单独跑；`interview` 能按顺序跑完           | 投前看简历可以演示之后；转写更重，后做  |
| **愿景**       | 知识库、模拟面试、真面试入库、企业查询（都做成新工具或新的老师命令） | 不作为本期必须交付                      |

默认顺序：M0 文档写定 → 书面简历合格线（内容与排版，可先用临时合格线）→ 投前看简历可以演示 → 听后做复盘。知识库及以后的能力，不作为本期必须交付。

「判能不能投」和「查排版」必须先有书面合格线（优先写在上游；未定稿前由维护者确认一份临时合格线）。没有书面合格线，这两个评价工具不要开 Issue，否则模型会自己发明一套「好简历」。PDF 出图、读简历不依赖标准，文档写定之后就可以做。本期只检查 PDF；Word 转 PDF 不作为本期必须交付。

## 5. 听后做复盘（待开）

| ID  | 建议标题                                        | 验收要点                                                                         |
| --- | ----------------------------------------------- | -------------------------------------------------------------------------------- |
| I1  | `feat(asr): 本机转写现场录音`                   | 默认 mlx-whisper `large-v3-turbo`；带时间的逐字稿；不使用云端语音识别            |
| I2  | `feat(qa): 从逐字稿还原问答`                    | 列出问了什么、大致怎么答；本步不评价作答好坏                                     |
| I3  | `feat(review): 面试评价`                        | 用面试作答的检查项，不用简历内容标准；不超过 3 条改法                            |
| I4  | `feat(cli): interview 按顺序调用并跳过已有文件` | 老师一条命令跑完 I1～I3；已有转写稿则跳过转写；`--resume` 须为 PDF；不运行查排版 |

听后做复盘做完的标志：维护者对若干段真面试现场录音跑通 `interview`，问答列表可供师生一起听时当提纲。详见 [产品说明第 11.2 节](../01-product/001_prd_就业守护助手产品说明.md)。
