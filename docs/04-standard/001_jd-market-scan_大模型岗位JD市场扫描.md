## 2. 岗位怎么分（读 JD 时先归类）

市场把「大模型」拆成几类，简历与合格线不要混成一种人：

| 类型          | 典型标题关键词                   | 企业更看什么                          |
| ------------- | -------------------------------- | ------------------------------------- |
| A. 应用落地   | 大模型应用、Agent 开发、智能应用 | RAG、Agent、工程化、业务场景交付      |
| B. 应用算法   | 大模型应用算法、RAG/Agent 算法   | 链路效果、评测、部分微调 / 推理优化   |
| C. 模型算法   | 预训练、SFT/RLHF、多模态训练     | 训练框架、数据策略、论文 / 大规模训练 |
| D. 训推 Infra | 推理引擎、训练平台、vLLM 等      | 性能、分布式、CUDA / 框架源码         |

**本仓本期学员工具默认对齐 A + B**（与维护者已定「大模型算法 / 应用」范围一致）。C / D 可作为水平线加分，不作为人人必须过的合格线。

## 3. 高频职责（出现多、且跨渠道重复）

按「出现很频繁 → 常见 → 加分」排列。频次为定性档，不是精确百分比。

### 3.1 几乎每份应用向 JD 都会写

| 主题       | JD 里常见说法（归纳）                                             |
| ---------- | ----------------------------------------------------------------- |
| RAG 全链路 | 文档解析、切分、Embedding、向量库、混合检索、Rerank、Query 改写   |
| Agent 编排 | 任务规划、工具调用、记忆、多 Agent、工作流 / 状态机、异常降级     |
| 业务落地   | 智能问答、知识库、客服 / 审查 / 运营助手等场景的 0→1 或持续迭代   |
| 效果与评测 | 幻觉控制、忠实度、命中率、A/B、offline/online eval、Bad Case 闭环 |
| 工程交付   | Python 服务化、API、Docker；常提到与业务系统对接                  |

### 3.2 常见（过半应用 / 应用算法岗）

| 主题           | JD 里常见说法                                        |
| -------------- | ---------------------------------------------------- |
| Prompt 工程    | 模板、结构化输出、CoT / ReAct、指令稳定性            |
| 微调           | LoRA / QLoRA、SFT；部分写 RLHF / 偏好对齐            |
| 推理部署       | vLLM 等推理引擎、量化、延迟与吞吐、私有化            |
| 向量与检索组件 | Milvus / ES / PGVector 等；不只「会调用 Chat API」   |
| 框架           | LangChain / LangGraph / LlamaIndex / Dify 等至少一种 |

### 3.3 加分或资深向

| 主题           | JD 里常见说法                                  |
| -------------- | ---------------------------------------------- |
| 多智能体与 MCP | Multi-Agent、Function Calling、MCP 工具生态    |
| 可观测与平台化 | 监控、版本管理、Prompt Registry、灰度 / 热更新 |
| 多模态         | OCR、音视频、图文混合知识库                    |
| 论文 / 开源    | 顶会、框架贡献（多见于算法岗，非应用岗硬门槛） |

## 4. 高频任职要求

| 维度     | 市场常见写法                        | 对学员简历的含义                         |
| -------- | ----------------------------------- | ---------------------------------------- |
| 学历     | 本科起；算法岗常写硕士优先          | 合格线不把「非硕士」当硬伤；水平线可区分 |
| 年限     | 应用岗常见 1～3 年 AI 相关；资深 3+ | 应届 / 转岗用**项目深度**补年限叙事      |
| 语言     | Python 几乎必备；部分要 Java/Go     | 简历须有可运行的工程痕迹，不只模型名词   |
| 项目证据 | 「完整落地 / 非 Demo」反复出现      | 个人 Demo 弱；要有链路、职责、结果       |
| 业务理解 | 能把需求落成 RAG/Agent 方案         | 项目背景要写痛点，不只要技术清单         |
