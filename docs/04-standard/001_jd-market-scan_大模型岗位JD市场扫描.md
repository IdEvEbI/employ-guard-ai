## 2. 岗位分类

市场将「大模型」相关岗位分为以下几类，简历与合格线不宜混用同一套要求：

| 类型          | 典型标题关键词                             | 企业更看什么                                     |
| ------------- | ------------------------------------------ | ------------------------------------------------ |
| A. 应用落地   | 大模型应用、Agent 开发、AIGC 应用工程      | RAG、Agent、工程化、业务场景交付                 |
| B. 应用算法   | 大模型应用算法、RAG/Agent 算法、Agent 算法 | 链路效果、评测、微调 / 推理优化、数据飞轮        |
| C. 模型算法   | 预训练、SFT/RLHF/DPO、多模态训练           | 训练框架、数据策略、论文 / 大规模训练            |
| D. 训推 Infra | 推理引擎、训练平台、vLLM / SGLang          | 性能、分布式、CUDA / 框架源码、PD 分离、KV Cache |

**本仓本期学员工具默认对齐 A + B**（大模型应用 / 应用算法）。C、D 可作为水平线加分，不作为人人必须通过的合格条件。

相对既有观察：B 类 JD 更常把 **offline/online eval、Harness、数据飞轮** 写入职责；D 类 JD 中 **SGLang、Prefill-Decode 分离、KV Cache 复用** 出现频率上升，但仍应与 A、B 分开看待。

## 3. 高频职责（跨渠道重复出现）

按「出现很频繁 → 常见 → 加分」排列。频次为定性档次，不是精确百分比。

### 3.1 应用向 JD 几乎都会写

| 主题       | JD 中常见说法（归纳）                                                               |
| ---------- | ----------------------------------------------------------------------------------- |
| RAG 全链路 | 文档解析、切分、Embedding、向量库、**混合检索（Dense + BM25）**、Rerank、Query 改写 |
| Agent 编排 | 任务规划、工具调用、记忆、多 Agent、工作流 / 状态机、ReAct / Plan-Execute、异常降级 |
| 业务落地   | 智能问答、知识库、客服 / 审查 / 运营助手、Copilot 类场景的 0→1 或持续迭代           |
| 效果与评测 | 幻觉控制、忠实度、命中率、A/B、offline/online eval、Bad Case 闭环、**Harness 评测** |
| 工程交付   | Python 服务化、API、Docker / K8s；与业务系统或数据管道对接                          |
| 安全与可控 | 权限、脱敏、内容审核、Guardrail、危险操作拦截、引用溯源                             |

### 3.2 常见（过半应用 / 应用算法岗）

| 主题            | JD 中常见说法                                                                |
| --------------- | ---------------------------------------------------------------------------- |
| Prompt / 上下文 | 模板、结构化输出、CoT / ReAct；**上下文压缩、窗口管理、Context Engineering** |
| 微调            | LoRA / QLoRA、SFT；应用算法岗常写 RLHF / RLAIF / DPO                         |
| 推理部署        | vLLM、量化、延迟与吞吐、私有化；部分写 SGLang                                |
| 向量与检索组件  | Milvus / ES / PGVector / Qdrant；强调不只「会调用 Chat API」                 |
| 框架            | **LangGraph**、LangChain、LlamaIndex、Dify / AutoGen 等至少一种              |
| 模型接入        | 通义、DeepSeek、GPT、Claude 等多模型 API 或私有化部署                        |
| 工具协议        | Function Calling / Tool Use、**MCP**；部分写 A2A                             |

### 3.3 加分或资深向

| 主题                | JD 中常见说法                                                |
| ------------------- | ------------------------------------------------------------ |
| 多智能体与平台化    | Multi-Agent、Agent Runtime / Infra、编排内核、可插拔工具生态 |
| 可观测与版本管理    | Tracing、成本监控、Prompt Registry、灰度 / 热更新            |
| 知识图谱与 GraphRAG | 图谱构建、GraphRAG、多跳推理、与向量检索融合                 |
| 多模态              | OCR、音视频、图文混合知识库、VL 模型                         |
| 论文 / 开源         | 发表论文或开源贡献（多见于 B / C 类，非 A 类硬门槛）         |
| 训推深度            | Megatron、DeepSpeed、CUDA kernel（多见于 C / D 类）          |

## 4. 高频任职要求

| 维度       | 市场常见写法                                                  | 对学员简历的含义                              |
| ---------- | ------------------------------------------------------------- | --------------------------------------------- |
| 学历       | 本科起；**应用算法 / Agent 算法岗常写硕士优先**               | 合格线不以「非硕士」为硬伤；水平线可区分      |
| 年限       | 应用岗 1～3 年 AI 相关；应用算法 3+ 或硕士可放宽              | 应届 / 转岗用**项目深度与评测证据**补年限叙事 |
| 语言       | **Python 几乎必备**；部分 B 类写 Go；Java 多见于与 002 重叠岗 | 须有可运行的 AI 链路，不能只有模型名词        |
| 项目证据   | 「完整落地 / 非 Demo / 线上真实用户」反复出现                 | 个人 Demo 偏弱；须有链路、职责、指标或评测    |
| 评测意识   | Harness、golden set、任务成功率、工具调用准确率               | 简历宜写评测做法或指标，不能只写功能清单      |
| 业务理解   | 能把需求落成 RAG/Agent 方案并迭代                             | 项目背景要写痛点与迭代，不能只要技术栈        |
| 业务域加分 | 金融、招聘、客服、知识库、Copilot 等垂直场景                  | 写清场景与约束（合规、时延、成本）            |
