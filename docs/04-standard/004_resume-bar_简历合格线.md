## 1. 使用范围

| 编号 | 口径                                                                                                              |
| ---- | ----------------------------------------------------------------------------------------------------------------- |
| R1   | 本期服务 **大模型应用 / 大模型应用算法** 投递向简历（对齐 001 的 A、B 类）；暂不覆盖其他学科或纯后端 / 测试等岗位 |
| R2   | 无具体企业岗位说明时，按通用大模型应用 / 应用算法面初筛；报告须标明非针对某一企业                                 |

## 2. 内容合格线（判能不能投）

任一硬伤成立 → **内容未合格**。未过合格线时，不输出「水平更高 / 更低」的排序结论。

对应关系见 003：C1↔S1，C3↔S4～S6，C4↔S8，C5↔S9，C6↔S10，C7↔S14～S17，C8↔S3，C9↔S13。

| 编号 | 检查项                       | 判定为「过」的条件                                                                                                                                                                                                                                                                                                                                   | 状态                         |
| ---- | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------- |
| C1   | 首页岗位类表述可辨           | **首页基本信息**须有岗位类表述（如智能体开发工程师、算法工程师、大模型应用工程师）。不强制「应聘岗位 / 求职意向」四字。仅靠项目或技能反推、首页看不出投什么岗 → **未合格**。有表述但与主业明显拧着 → **存疑**                                                                                                                                        | 已确认（对齐 003 S1 v0.3.2） |
| C2   | 可联系                       | 有可用手机或邮箱至少一项。**不因使用 QQ 邮箱判不合格**                                                                                                                                                                                                                                                                                               | 已确认                       |
| C3   | 算法 + RAG + Agent 证据齐全  | 须**同时**具备三类可追问证据：① **算法 / 模型**（微调、Prompt / 上下文优化、offline eval / Bad Case / Harness 等至少一种可说明）；② **RAG**（不只向量库名词，须能说明链路中至少两段，如切分、混合检索 / 精排、生成、溯源 / 拒答）；③ **Agent**（规划、Function Calling / MCP / 工具编排、记忆、降级等至少一项，且写明本人职责）。缺一类 → 未合格     | 已确认（对齐 003 S4～S6）    |
| C4   | 至少 1 个可追问项目          | 有独立项目块，或工作经历中有同等深度的项目叙述；含背景或问题、本人职责、所用技术                                                                                                                                                                                                                                                                     | 已确认（对齐 003 S8）        |
| C5   | 职责可核实                   | 有具体动作（搭建、微调、混合检索 / 精排、评测 / Harness、部署、Tool / MCP 编排等），不是只有「熟悉 / 了解 / 负责推进」。**多个项目一律写「项目负责人」且年限不长** → **存疑**（`pass` 仍可为 true）                                                                                                                                                  | 已确认（对齐 003 S9）        |
| C6   | 结果可追问                   | 有业务结果、效率、指标或规模等可追问的结果表述即可；**不强制**量化数字。无数字但方案具体 → 可过合格线。量化与评测完整度进入水平线 H4。**明显离谱、面试难以辩护的指标或技术选型 / 规模**（如小参数扛金融研报主生成、框架职责写糊、向量量级与生产叙事冲突）→ **存疑**（`doubtful=true`，`pass` 仍可为 true）（003 S19）                                | 已确认（对齐 003 S10、S19）  |
| C7   | 时间线基本自洽               | ① 项目时间落在对应在职段内，不跨未列明的单位（003 S14）；② 年龄、学历、工作年限在简历上**互算明显不通** → **存疑**（003 S15）；③ 空窗、频繁极短任见水平线 H8，**不单独**判未合格（003 S16、S17）；④ **工作 / 项目结束年月晚于检查当日**（进行中须写「至今」）→ **存疑**（003 S18；规则层以运行当日为基准）。**不核验与档案是否一致**（003 §3.1、§5） | 已确认（含 S18）             |
| C8   | 技能与项目证据不严重脱节     | 大段技能堆砌但项目无法支撑时，判未合格或存疑                                                                                                                                                                                                                                                                                                         | 已确认（对齐 003 S3）        |
| C9   | 工作履历须有 AI 相关主业支撑 | **个人项目为主、且工作履历非 AI** → **不能过合格线**。非 AI 工作经历本身不单独构成硬伤（见 H1）；若最近主业与目标岗无关、且主要证据全是个人项目、无法对应工作产出 → 未合格                                                                                                                                                                           | 已确认（对齐 003 S13）       |

### 2.1 内容水平线（仅过合格线后使用）

输出为 **高 / 中 / 低**（JSON：`level` = `high` \| `mid` \| `low`）。细则与举例见 [003 §4](./003_resume-standard_简历书写标准.md)。禁止「沾边即高」。

| 编号 | 检查项     | 高（摘要）                                | 中（摘要）                       | 低（摘要）                          |
| ---- | ---------- | ----------------------------------------- | -------------------------------- | ----------------------------------- |
| H1   | 履历相关度 | 岗位名与目标方向、主业即 AI 交付          | 岗位名偏泛，或意向与项目职称拧着 | 非 AI 占主视觉或方向拧着            |
| H2   | 链路完整度 | 主项目闭环且职责落在链上                  | 有环节但串不成闭环               | 仅框架名 / 单点                     |
| H3   | 工程化     | 服务化 / 流式 / 测试 / 部署 / 降级≥两类   | 工具名一带而过                   | 几乎无工程落地                      |
| H4   | 评测与量化 | 有口径或前后对比，数字可辩护              | 有数字但弱；可信度一般           | 无结果或数字离谱（可并 C6 存疑）    |
| H5   | 场景深度   | 对象 / 痛点 / 入口或业务闭环；技术清单≠高 | 有场景名、职责仍是技术清单       | 纯名词堆砌                          |
| H6   | 信息密度   | 1～3 深项目，主深次短，无凑页             | 深但说明书感或凑页               | 多浅项或过长堆砌                    |
| H7   | 市场加分项 | 热点能力写入职责与结果且可追问            | 技能区有、项目一带               | 仅罗列                              |
| H8   | 履历稳定性 | 衔接清楚且近段「至今」                    | 近段已结束无「至今」；或小空窗   | 频繁极短任；或结束时间在未来（S18） |

## 3. 排版合格线（查排版；只看页图）

任一硬伤成立 → **排版未合格**。

| 编号 | 检查项         | 判定为「过」的条件                                                               | 状态                    |
| ---- | -------------- | -------------------------------------------------------------------------------- | ----------------------- |
| P1   | 页数可控       | 投递 PDF 总页数 **≤ 4 页**；超过 4 页 → 排版未合格。无单独封面页约定时按总页数计 | 已确认（对齐 003 §2.2） |
| P2   | 无严重溢出     | 正文无大面积出框、叠字、切字                                                     | 已确认                  |
| P3   | 结构可扫读     | 能较快定位技能、项目或工作等主块；版式不致无法扫读                               | 已确认                  |
| P4   | 留白不过分极端 | 不是近乎空白凑页，也不是完全无层级的文字墙（末页过短可标「可改」）               | 已确认                  |
| P5   | 水印例外       | **校区或试用类贴图水印不判不合格**                                               | 已确认（对齐 003 §2.2） |

## 4. 明确不做

- 不凭文本给出排版结论；不凭页图给出内容「能否投递」的替代结论。
- 不把课评「好课标准」用到简历上。
- 不打百分制分数替代老师分批。
- 不因文辞华丽判合格；不因非 AI 早期经历单独判未合格（见 H1、C9）。
- 不因空窗、频繁跳槽或单段任职短**单独**判内容未合格（见 C7、H8；细则见 003 §3.4）。
- **不核验**年龄、学历是否与档案一致，也不因此判内容未合格（见 C7；细则见 003 §3.1、§5）。
- 本期清单不扩展到其他学科岗位的合格线；不将 Java 全栈、Spring Boot 等 002 向要求写入大模型学科内容合格线。
