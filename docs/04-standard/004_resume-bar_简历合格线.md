## 1. 使用范围

| 编号 | 口径                                                                                                              |
| ---- | ----------------------------------------------------------------------------------------------------------------- |
| R1   | 本期服务 **大模型应用 / 大模型应用算法** 投递向简历（对齐 001 的 A、B 类）；暂不覆盖其他学科或纯后端 / 测试等岗位 |

## 2. 内容合格线（判能不能投）

任一硬伤成立 → **内容未合格**。未过合格线时，不输出「水平更高 / 更低」的排序结论。

对应关系见 003：C1↔S1，C3↔S4～S6，C4↔S8，C5↔S9，C6↔S10，C7↔S14～S17，C8↔S3，C9↔S13。

| 编号 | 检查项                       | 判定为「过」的条件                                                                                                                                                                                                                                                                                                                               | 状态                      |
| ---- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------- |
| C1   | 岗位方向可辨                 | 不强制单独出现「求职意向」字段；全文须能判断为大模型应用或应用算法。无法判断 → 未合格                                                                                                                                                                                                                                                            | 已确认（对齐 003 S1）     |
| C2   | 可联系                       | 有可用手机或邮箱至少一项。**不因使用 QQ 邮箱判不合格**                                                                                                                                                                                                                                                                                           | 已确认                    |
| C3   | 算法 + RAG + Agent 证据齐全  | 须**同时**具备三类可追问证据：① **算法 / 模型**（微调、Prompt / 上下文优化、offline eval / Bad Case / Harness 等至少一种可说明）；② **RAG**（不只向量库名词，须能说明链路中至少两段，如切分、混合检索 / 精排、生成、溯源 / 拒答）；③ **Agent**（规划、Function Calling / MCP / 工具编排、记忆、降级等至少一项，且写明本人职责）。缺一类 → 未合格 | 已确认（对齐 003 S4～S6） |
| C4   | 至少 1 个可追问项目          | 有独立项目块，或工作经历中有同等深度的项目叙述；含背景或问题、本人职责、所用技术                                                                                                                                                                                                                                                                 | 已确认（对齐 003 S8）     |
| C5   | 职责可核实                   | 有具体动作（搭建、微调、混合检索 / 精排、评测 / Harness、部署、Tool / MCP 编排等），不是只有「熟悉 / 了解 / 负责推进」                                                                                                                                                                                                                           | 已确认（对齐 003 S9）     |
| C6   | 结果可追问                   | 有业务结果、效率、指标或规模等可追问的结果表述即可；**不强制**量化数字。无数字但方案具体 → 可过合格线；量化与评测完整度进入水平线                                                                                                                                                                                                                | 已确认（对齐 003 S10）    |
| C7   | 时间线基本自洽               | ① 项目时间落在对应在职段内，不跨未列明的单位（003 S14）；② 年龄、学历、工作年限在简历上**互算明显不通** → **存疑**（老师复核，不自动等同内容未合格）（003 S15）；③ 空窗、频繁极短任见水平线 H8，**不单独**判未合格（003 S16、S17）。**本工具不核验年龄、学历是否与档案一致，也不因此判内容未合格**（003 §3.1、§5）                               | 已确认                    |
| C8   | 技能与项目证据不严重脱节     | 大段技能堆砌但项目无法支撑时，判未合格或存疑                                                                                                                                                                                                                                                                                                     | 已确认（对齐 003 S3）     |
| C9   | 工作履历须有 AI 相关主业支撑 | **个人项目为主、且工作履历非 AI** → **不能过合格线**。非 AI 工作经历本身不单独构成硬伤（见 H1）；若最近主业与目标岗无关、且主要证据全是个人项目、无法对应工作产出 → 未合格                                                                                                                                                                       | 已确认（对齐 003 S13）    |

### 2.1 内容水平线（仅过合格线后使用）

| 编号 | 检查项     | 较高水平的信号                                                                                                              |
| ---- | ---------- | --------------------------------------------------------------------------------------------------------------------------- |
| H1   | 履历相关度 | 工作经历与大模型 / AI 工程相关；非 AI 经历**只影响水平线**，不单独判内容未合格                                              |
| H2   | 链路完整度 | RAG：解析 → 切分 → 混合检索 → 精排 → 生成 → 评测或兜底；Agent：状态、MCP / Tool、人在回路、降级；Context Engineering 有实践 |
| H3   | 工程化     | 服务化、私有化部署、缓存、监控、结构化输出、Guardrail / 权限 / 脱敏等                                                       |
| H4   | 评测与量化 | 有 Harness / golden set、任务成功率、工具调用准确率 / 幻觉率、前后对比；无数字但方案具体者合格线可通过，水平线偏低          |
| H5   | 场景深度   | 垂直场景痛点清楚，方案针对痛点，而非技术名词堆砌                                                                            |
| H6   | 信息密度   | 1～3 个深项目优于多个浅项目；避免说明书式冗长                                                                               |
| H7   | 市场加分项 | LangGraph、GraphRAG、多模型路由、引用溯源等写入项目且经得住追问（**非合格线硬性要求**）                                     |
| H8   | 履历稳定性 | 在职衔接合理、空窗可说明；无「每段均极短、短期多次换岗」的整体印象（**仅水平线 / 存疑**，见 003 S16、S17）                  |

## 4. 明确不做

- 不凭文本给出排版结论；不凭页图给出内容「能否投递」的替代结论。
- 不把课评「好课标准」用到简历上。
- 不打百分制分数替代老师分批。
- 不因文辞华丽判合格；不因非 AI 早期经历单独判未合格（见 H1、C9）。
- 不因空窗、频繁跳槽或单段任职短**单独**判内容未合格（见 C7、H8；细则见 003 §3.4）。
- **不核验**年龄、学历是否与档案一致，也不因此判内容未合格（见 C7；细则见 003 §3.1、§5）。
- 本期清单不扩展到其他学科岗位的合格线；不将 Java 全栈、Spring Boot 等 002 向要求写入大模型学科内容合格线。
